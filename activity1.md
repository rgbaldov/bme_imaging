## 2. Theoretical Overview
### 2.1 The DICOM Part 10 Architecture
Every standard-compliant DICOM Part 10 file begins with a 128-byte preamble, followed immediately by the 4-byte ASCII prefix `DICM`:
$$\text{Preamble (128 bytes)} \;\Vert{}\; \text{"DICM" (4 bytes)} \;\Vert{}\; \text{File Meta Information (Group 0002)} \;\Vert{}\; \text{Dataset}$$

Each Data Element inside a DICOM file consists of:
* **Tag:** A 32-bit identifier represented as `(GGGG, EEEE)` where $G$ is the Group and $E$ is the Element.
* **Value Representation (VR):** A 2-byte code indicating data types (e.g., `PN` for Person Name, `DA` for Date, `CS` for Code String, `DS` for Decimal String).
* **Value Length:** The size of the payload in bytes.
* **Value Field:** The actual binary or string data.

### 2.2 CT Radiometric Calibration & Windowing
Raw values generated by CT detector arrays do not represent linear Hounsfield Units directly. They must first be linearly rescaled using the metadata parameters `Rescale Slope` ($m$) and `Rescale Intercept` ($b$):
$$\text{HU} = (\text{Pixel Value} \times m) + b$$

Because the human eye can only resolve roughly 30 to 100 shades of gray simultaneously, diagnostic review relies on contrast windowing:
$$\text{Lower Bound} = c - \frac{w}{2}, \quad \text{Upper Bound} = c + \frac{w}{2}$$

where $c$ is the `Window Center` and $w$ is the `Window Width`.
